# 媒体分发台

本地运行的图文分发项目。管理多个媒体账户、图文素材和待分发任务；当前接入 **抖音图文**，通过浏览器自动化操作创作者中心。

## 启动

需要 Node.js 20 或更新版本。Windows 可双击 `启动媒体分发台.bat`。也可以在项目目录运行：

```powershell
npm install
npx playwright install chromium
npm start
```

随后打开 http://127.0.0.1:4173 。服务只监听本机地址。

## 使用流程

1. 添加抖音账户。每个账户都可以单独点“打开登录”，在弹出的浏览器中扫码或手动登录，登录后点“完成登录”。
2. 创建图文素材，为每条内容选择一个发布平台，添加 1–12 张图片（可分批添加并移除），填写标题和正文。已有素材可编辑标题、正文、图片和配乐；修改只影响之后创建的任务，已有任务使用创建时保存的素材快照。没有关联分发任务的素材可以删除，未被其他素材或任务引用的上传图片也会删除；已有任务的素材会保留，以维护任务和发布记录。
3. 选择素材，每条任务只能选择该平台的一个账户，也可以选择“随机选择一个账户”。设置计划时间或立即加入队列。若同一素材需要再次发布，请再创建一条任务。
4. 保持本地服务运行。后台每 5 秒检查到期任务。发布成功会标记为“已发布”；无法判断发布结果时会显示“需核对”并保存截图。

登录资料、素材、队列和截图保存在 `data/`，不会上传到本项目的服务器。请妥善保护这台电脑的账户资料，并定期备份 `data/`。移除账户不会自动删除其登录资料。

## 当前范围

- 平台结构按媒体和账户分层，后续可在 `src/publishers/` 增加其他媒体发布器。
- 当前只实现抖音图文。指定配乐时，发布器会搜索抖音曲库并选择同名歌曲；搜索不到会在点击发布前报错。抖音页面改版、验证码、上传处理和账户权限可能影响自动发布；遇到安全验证请手动完成登录，遇到“需核对”请先在抖音检查是否已经发布。
- 已使用一个抖音账户完成过图文端到端发布验证；页面和账户状态仍可能变化，出现“需核对”时先检查抖音作品管理，避免重复发布。

## 本地 Agent 导入素材

Agent 可以直接调用 `/api/uploads` 上传图片，再调用 `/api/posts` 保存图文。也可以把标题、正文、平台和相对图片路径写入 JSON 文件，通过 `node scripts/import-post.mjs 图文内容.json` 一次完成两步；示例见 `data/generated/cola-wings-post.json`。导入只保存素材，不创建发布任务。

## 项目结构

- `src/server.js`：本地服务、账户与素材接口、任务调度
- `src/store.js`：本地 JSON 持久化
- `src/publishers/douyin.js`：抖音浏览器发布器
- `public/`：管理界面
